0) 변수 (그대로 복붙)
$PROJECT   = "quali-journal-prod"
$REG_SRC   = "asia-northeast3"      # 서울: SRC(소스 빌드)
$REG_LIVE  = "asia-northeast1"      # 도쿄: LIVE(도메인)
$SRC       = "quali-journal-admin"
$LIVE      = "quali-admin-domap"

1) 진단(10초) — 정확한 원인 문장 뽑기
gcloud run services describe $SRC  --region $REG_SRC  --project $PROJECT --format="value(status.conditions[-1].message)"
gcloud run services describe $LIVE --region $REG_LIVE --project $PROJECT --format="value(status.conditions[-1].message)"
# 두 줄 모두 'Container import failed'면 권한 이슈 확정

2) 권한 한 방에 고정 (프로젝트 + 저장소 레벨)
# 2-1) 런타임 서비스계정 조회
$SA_SRC  = gcloud run services describe $SRC  --region $REG_SRC  --project $PROJECT --format "value(spec.template.spec.serviceAccountName)"
$SA_LIVE = gcloud run services describe $LIVE --region $REG_LIVE --project $PROJECT --format "value(spec.template.spec.serviceAccountName)"
$PN      = gcloud projects describe $PROJECT --format "value(projectNumber)"

# 2-2) 프로젝트 레벨 권한(읽기/시크릿)
gcloud projects add-iam-policy-binding $PROJECT --member "serviceAccount:$SA_SRC"  --role "roles/artifactregistry.reader"
gcloud projects add-iam-policy-binding $PROJECT --member "serviceAccount:$SA_LIVE" --role "roles/artifactregistry.reader"
gcloud projects add-iam-policy-binding $PROJECT --member "serviceAccount:$SA_SRC"  --role "roles/secretmanager.secretAccessor"
gcloud projects add-iam-policy-binding $PROJECT --member "serviceAccount:$SA_LIVE" --role "roles/secretmanager.secretAccessor"

# 2-3) Cloud Build SA는 writer(이미 있으면 OK)
gcloud projects add-iam-policy-binding $PROJECT --member "serviceAccount:$PN@cloudbuild.gserviceaccount.com" --role "roles/artifactregistry.writer"

# 2-4) 저장소(repository) 단위 바인딩도 추가(조직 정책 방어)
# SRC의 최신 이미지 경로에서 REPO/LOCATION을 추출
$IMG = gcloud run services describe $SRC --region $REG_SRC --project $PROJECT --format "value(spec.template.spec.containers[0].image)"
# 예: asia-northeast3-docker.pkg.dev/quali-journal-prod/containers/quali-admin@sha256:...

# 저장소 이름(프로젝트 다음 세그먼트)과 위치 추출
$repo = ($IMG -split "/")[2]                  # 예: containers
$loc  = ($IMG -split "-docker\.pkg\.dev")[0]  # 예: asia-northeast3

gcloud artifacts repositories add-iam-policy-binding $repo --location $loc --project $PROJECT `
  --member "serviceAccount:$SA_SRC"  --role "roles/artifactregistry.reader"
gcloud artifacts repositories add-iam-policy-binding $repo --location $loc --project $PROJECT `
  --member "serviceAccount:$SA_LIVE" --role "roles/artifactregistry.reader"


이유: 프로젝트 레벨 Reader만으론 조직/리소스 정책으로 막히는 케이스가 있어 저장소 레벨 Reader를 같이 주면 재발 방지.

3) 정석 배포 루틴 (SRC 소스 빌드 → LIVE 승격 → 최신 트래픽)
# 3-1) SRC(서울) 소스에서 재빌드(정적 HTML 포함)
gcloud run deploy $SRC `
  --source . `
  --region $REG_SRC --project $PROJECT `
  --allow-unauthenticated `
  --set-secrets "ADMIN_TOKEN=ADMIN_TOKEN:latest" `
  --set-env-vars "PYTHONUTF8=1,PYTHONIOENCODING=utf-8"

# 3-2) 새 이미지 URI 추출 → LIVE(도쿄) 승격
$IMG = gcloud run services describe $SRC `
  --region $REG_SRC --project $PROJECT `
  --format "value(spec.template.spec.containers[0].image)"

gcloud run deploy $LIVE --image $IMG `
  --region $REG_LIVE --project $PROJECT `
  --platform managed --allow-unauthenticated `
  --set-secrets "ADMIN_TOKEN=ADMIN_TOKEN:latest" `
  --set-env-vars "PYTHONUTF8=1,PYTHONIOENCODING=utf-8"

# 3-3) 최신 리비전에 100% 트래픽 (PowerShell은 쌍따옴표/변수확장 주의)
gcloud run services update-traffic $LIVE --to-latest `
  --region $REG_LIVE --project $PROJECT


이 순서가 SSOT 루틴이고, LIVE는 도메인 매핑 전용 서비스(도쿄)라 SRC 이미지를 승격해야 라이브가 교체됨.



































1) 현재 변수 재확인
$PROJECT="quali-journal-prod"
$SERVICE="quali-journal-admin"
$REGION="asia-northeast3"

2) 레포에 있는 최신 다이제스트 가져오기

quali 레포의 $SERVICE 이미지를 최신 1건만 뽑아와서 다이제스트 변수 만들기

# 최신 다이제스트 한 건
$DIGEST = (gcloud artifacts docker images list "$REGION-docker.pkg.dev/$PROJECT/quali/$SERVICE" `
  --format="value(DIGEST)" | Select-Object -First 1)

# 점검: 비어있으면 안 됨(아무것도 안 나오면 레포/권한/서비스명부터 다시 봐야 함)
$DIGEST


출력 예: sha256:4f0e...

아무 것도 안 나오면 → 방금 입력한 경로에 오타 없는지 확인:
asia-northeast3-docker.pkg.dev/quali-journal-prod/quali/quali-journal-admin
(맞는데도 비면 gcloud auth/권한 이슈니 알려줘)

3) 완전수식 이미지 경로 만들기(@sha256 사용)
$IMG_FQDN = "$REGION-docker.pkg.dev/$PROJECT/quali/${SERVICE}@$DIGEST"
$IMG_FQDN


출력 예: asia-northeast3-docker.pkg.dev/quali-journal-prod/quali/quali-journal-admin@sha256:4f0e...

4) 이미지 배포 (소스 배포 아님)
gcloud run deploy $SERVICE `
  --image "$IMG_FQDN" `
  --region $REGION --project $PROJECT --platform managed `
  --allow-unauthenticated `
  --set-secrets ADMIN_TOKEN=ADMIN_TOKEN:latest `
  --set-env-vars "PYTHONUTF8=1,PYTHONIOENCODING=utf-8"

5) 트래픽 최신화 + 열기
gcloud run services update-traffic $SERVICE --to-latest --region $REGION --project $PROJECT
$URL = (gcloud run services describe $SERVICE --region $REGION --project $PROJECT --format="value(status.url)")
Start-Process "$URL/?v=$(Get-Random)"

6) 스모크(200 / 401 / 200 기대)
$TOKEN = (gcloud secrets versions access latest --secret=ADMIN_TOKEN --project $PROJECT | Out-String).Trim()
curl.exe -s -o NUL -w "%{http_code}`n" "$URL/health"
curl.exe -s -o NUL -w "%{http_code}`n" "$URL/api/status"
curl.exe -s -o NUL -w "%{http_code}`n" -H "Authorization: Bearer $TOKEN" "$URL/api/status"


이제 매번 같은 절차로 코드 수정 → 배포 → 최신 반영을 3분 컷으로 끝내는 초딩 버전 최종 워크플로우를 남겨둘게.
(그대로 따라만 하면 항상 성공 루트)

초딩 버전 – “코드 수정 → 라이브 반영” 워크플로우
SSOT (고정 값)
$PROJECT ="quali-journal-prod"
$SRC     ="quali-journal-admin"   # 테스트(run.app, 서울)
$LIVE    ="quali-admin-domap"     # 라이브(도메인, 도쿄)
$REG_SEO ="asia-northeast3"
$REG_TYO ="asia-northeast1"
gcloud config set project $PROJECT

1단계) 코드 수정 → GitHub main에 푸시

server_quali.py, index.html, tools/* 등 수정 후 main 커밋

Actions(자동 CI) 성공(✔️) 확인

(확인) 소스 서비스가 쓰는 최신 이미지(@sha256) 얻기
$IMG_SRC = (gcloud run services describe $SRC --region $REG_SEO --format="value(spec.template.spec.containers[0].image)")
$IMG_SRC   # 예: asia-northeast3-docker.pkg.dev/…/quali/quali-journal-admin@sha256:XXXX


비어있으면:

$DIGEST = (gcloud artifacts docker images list "$REG_SEO-docker.pkg.dev/$PROJECT/quali/$SRC" --format="value(DIGEST)" | Select-Object -First 1)
$IMG_SRC = "$REG_SEO-docker.pkg.dev/$PROJECT/quali/$SRC@$DIGEST"

2단계) 같은 이미지를 라이브 서비스에 승격 배포

(권한은 한 번만 붙여두면 됨)

# 런타임 SA가 이미지 읽기 가능하도록(1회/재발 시만)
$SA_RUNTIME = (gcloud run services describe $LIVE --region $REG_TYO --format="value(spec.template.spec.serviceAccountName)")
gcloud artifacts repositories add-iam-policy-binding quali `
  --location $REG_SEO `
  --member "serviceAccount:$SA_RUNTIME" `
  --role "roles/artifactregistry.reader" `
  --project $PROJECT

# 이미지 배포(소스 X, 이미지 O)
gcloud run deploy $LIVE `
  --image "$IMG_SRC" `
  --region $REG_TYO --project $PROJECT --platform managed `
  --allow-unauthenticated `
  --set-secrets ADMIN_TOKEN=ADMIN_TOKEN:latest `
  --set-env-vars "PYTHONUTF8=1,PYTHONIOENCODING=utf-8"

3단계) 최신 리비전 100% + 캐시 무시 열기
gcloud run services update-traffic $LIVE --to-latest --region $REG_TYO --project $PROJECT
$URL_LIVE = (gcloud run services describe $LIVE --region $REG_TYO --project $PROJECT --format="value(status.url)")
Start-Process "$URL_LIVE/?v=$(Get-Random)"                # run.app
Start-Process "https://admin.standardai.co.kr/?v=$(Get-Random)"  # 도메인

4단계) 라이브 데이터 싱크(Ready 생성)

(컨테이너가 분리라 테스트에서 만든 자료가 라이브에 자동 반영되지 않음 → 라이브에서 한 번만 실행)

$TOKEN=(gcloud secrets versions access latest --secret=ADMIN_TOKEN --project $PROJECT | Out-String).Trim()

# JSON 구조 복구 + 발행본 재작성
curl.exe -s -o NUL -w "%{http_code}\n" -H "Authorization: Bearer $TOKEN" "$URL_LIVE/api/tools/repair"

# 상위 N 자동 승인(게이트 충족)
curl.exe -s -o NUL -w "%{http_code}\n" -H "Authorization: Bearer $TOKEN" "$URL_LIVE/api/tools/approve_top?n=20"

5단계) 스모크 + 화면 확인
curl.exe -s -o NUL -w "%{http_code}\n" "$URL_LIVE/health"           # 200
curl.exe -s -o NUL -w "%{http_code}\n" "$URL_LIVE/api/status"       # 401(무토큰)
curl.exe -s -o NUL -w "%{http_code}\n" -H "Authorization: Bearer $TOKEN" "$URL_LIVE/api/status"  # 200


브라우저에서 ADMIN_TOKEN 입력 → 인증됨(초록)

왼쪽 KPI 새로고침 / Ready 불러오기 → 카드 목록 보이면 완료

실패 패턴 ↔ 즉시 처방 (30초)
증상	즉시 조치
Container import failed	quali 레포에 런타임 SA에 artifactregistry.reader 붙였는지 확인. (위 2단계 권한 줄 재실행)
도메인만 옛 화면	3단계의 update-traffic + ?v=$(Get-Random)로 캐시 무시
Ready가 비어있음	4단계의 /api/tools/repair, /api/tools/approve_top 다시 실행
401 Unauthorized	브라우저 상단에서 토큰 재입력 (헤더 자동 부착 확인)
Health 200인데 Status 5xx	server_quali.py 최신 배포 여부 확인(1단계 CI 초록 + 2단계 이미지 승격)
