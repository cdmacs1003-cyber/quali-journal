# 퀄리저널 전체 개발 파일 사전 (한글판)
> 7개 항목(1. 파일 경로 / 2. 유형 / 3. 기능 요약 / 4. API / 5. UI/연계 / 6. 디렉터리/파일군 설명 / 7. 고도화 참고 포인트)을 모두 포함한 파일 사전입니다.  
> 배포/운영은 Cloud Run 기준, 관리자 UI는 단일 `index.html` 기준입니다.

---

## A. 최상위 핵심 파일/폴더

| 1. 파일 경로 | 2. 유형 | 3. 기능 요약 | 4. API 엔드포인트(해당 시) | 5. UI/연계 | 6. 디렉터리/파일군 설명 | 7. 고도화 참고 포인트 |
|---|---|---|---|---|---|---|
| `/server_quali.py` | Python(FastAPI 백엔드) | 관리자 API 서버의 엔트리포인트. 상태·설정·작업 흐름(SSE 포함)·보고서/요약/내보내기·로그 뷰 등 핵심 라우트 제공. `index.html` 서빙과 `/archive` 정적 파일 마운트도 담당. 인증 토큰 헤더 검증 포함. | 예: `/api/report`, `/api/enrich/*`, `/api/export/*`, `/api/flow/*`, `/api/tasks/*`, `/api/logs/*` | Admin UI의 모든 버튼 fetch가 이 백엔드로 연결. 실시간 작업은 SSE 스트림으로 로그 패널에 표시. | **코어** 앱 모듈. 오케스트레이터 서브프로세스 호출과 설정/보안/정적자산 서빙을 총괄. | 단일 파일 비대화 → 라우터/서비스 분리, 테스트 보강 권장. 대용량 작업은 백그라운드/큐 도입 고려. |
| `/admin/index.html` | HTML(관리자 UI) | 단일 HTML로 구성된 관리자 대시보드. KPI, 승인/발행, 보고서/요약/내보내기, “원클릭 플로우” 등 버튼 제공. 토큰 입력/해제 UI와 런타임·빌드 배지 노출. | (해당 없음) | 각 버튼 클릭 → fetch → FastAPI 라우트 호출. SSE 로그 영역으로 진행 상황 실시간 표시. | **admin** UI 모듈. 서버가 `/`에서 서빙. | 프론트 단일 파일 → 모듈화/컴포넌트화 여지. ‘QA 자동 점검’ 등 확장 슬롯 존재. |
| `/orchestrator.py` | Python(CLI 오케스트레이터) | 수집·선정·발행 파이프라인 실행. `--collect-community`, `--collect-keyword`, `--approve-keyword-top`, `--publish-keyword` 등 플래그 조합으로 데일리/키워드 작업 실행. | (API 아님: 서버가 서브프로세스로 실행) | UI 버튼(예: “커뮤니티 수집/키워드 실행/원클릭”) → 서버 라우트 → 오케스트레이터 호출 → 결과 JSON/아카이브 파일 생성. | **엔진** 역할. feeds/config를 읽어 JSON 산출(`selected_*`). | 현 버전은 간소화 경향. QG/FC(품질·팩트)·스코어링 고도화 재도입 필요. |
| `/config.json` | JSON(설정) | 게이트 임계값, 커뮤니티 필터/임계치, 기능 토글 등 운영 파라미터. 발행은 승인 ≥ 15가 기본. | (해당 없음) | 슬라이더로 게이트 변경→ `PATCH /api/config/gate_required`. KPI/상태에 즉시 반영. | 시스템 동작 전역 설정의 SSOT. | 임계값/필터를 운영자가 쉽게 조정할 수 있게 UI 확장 검토. |
| `/data/` | 폴더(JSON 저장) | 선택본/작업본 JSON 등의 저장 위치(선택). 백엔드는 경로를 유연 탐색. | (해당 없음) | UI에는 직접 노출 X. API가 내부에서 읽어 KPI·리스트 구성. | 데이터 파일 보관(로컬 모드). 클라우드에선 DB로 대체 가능. | 대량/동시 작업 시 파일 I/O 경합 → DB 이전 고려. |
| `/archive/` | 폴더(아카이브) | 일일 보고서(MD/HTML), 요약본(MD), JSON 결과물 날짜별 보관. 충돌 시 `_HHMM` 타임스탬프 부여 권고. | (해당 없음) | UI에서 “보고서 열기/다운로드” 링크로 접근. 정적 서빙 `/archive` 마운트. | 결과물 보관의 SSOT. 백업 정책 필요. | GCS 버저닝/보존정책으로 영구 보관 권장. |
| `/tools/` | 폴더(유틸 스크립트) | 승인·동기화·수선·리포트 등 오프라인/보정 작업 모음. 일부는 `/api/tools/*`로 호출. | 예: `/api/tools/approve_top`, `/api/tools/repair` 등. | UI 버튼은 제한적. 서버가 서브프로세스로 실행. | 관리 유틸 집합. | 점차 서버 내 로직으로 흡수·테스트 자동화 권장. |

| `/selected_keyword_articles.json` | JSON(작업본) | 하루 키워드(또는 일일) 수집 결과의 **작업본**. 기사 메타·점수·승인여부 등이 담김. 발행 전 편집자가 승인 플래그와 코멘트를 부여. | (간접) `/api/status` 등에서 스냅샷 조회. | UI의 “Ready 불러오기/리스트”가 이 파일 기반. 승인 토글 시 서버가 저장. | 오케스트레이터 출력이자 UI 입력. | 파일 I/O 대신 DB로 이관 고려(동시성/원자성 개선). |
| `/selected_articles.json` | JSON(발행본) | **최종 승인본**. 발행 대상만 모은 결과로, 보고서/내보내기에서 사용. | `/api/export/md`, `/api/export/csv` 등에서 사용. | UI는 경로 링크만 표기(파일은 정적으로 제공). | 발행 SSOT JSON. | 버전 기록/복구 기능(스냅샷) 추가 고려. |
| `/_inventory/inventory.json` | JSON(파일 인벤토리) | 전체 파일/해시 목록의 SSOT. 변경 검출·일관성 검사용. | (해당 없음) | 런타임 비사용, 개발/배포 검증용. | 문서·품질 관리 체계 일부. | 변경 자동 반영 스크립트(프리커밋/CI) 연동 권장. |

- 본 파일 사전은 **현행 Cloud Run 배포 + 단일 Admin UI** 기준입니다.
- 운영 시에는 **SSOT 문서(운영/배포/런북)**와 함께 사용해 주세요.
- 추가 파일군(예: tests/, docs/)이나 상세 내부 함수 시그니처는 팀 내 레포지토리 원본을 참고하세요.
